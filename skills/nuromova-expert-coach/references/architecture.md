# 工作流架构

一个专家入口协调四个独立功能 Skill：场景生成 → Coach 模拟 → 专家访谈 → 知识编辑。专家可以跳转或只使用其中一项。具体路由见上级 SKILL.md。

共享正文位于本地项目 knowledge/，会话记录位于被 Git 忽略的 review-data/；GitHub 管理共享版本。场景、专家反馈和知识结论分开记录，模拟运动者回答不作为科学来源。

知识卡支持输入解释、有效问题、运动表现判断、条件化行动和复评。目录检查、模型演示、专业审阅和正式检索发布分别记录，互不替代。当前没有自动发布运行时。

三类可编辑资产与 Skill 特殊修改流程统一见 [维护边界](../../../docs/expert-maintenance.md)。场景生成读取输入模型；Coach 模拟读取 Agent 架构；两者按需读取知识库。执行层不复制业务规则。

## 可迁移的 Coach 核心

设计入口见 [agent/README.md](../../../agent/README.md)。核心最小单元是一轮运动者事件处理，输出下一步动作和新状态；专家模式切换属于外围工作台。专业知识留在 knowledge/，决策协议与验证设计留在 agent/。模拟使用这些规则，产品实现需提供输入、检索、状态存储与模型适配，并经实际验证。
