# 知识结构与交付
主入口：AI coach相关文档 / RAG库知识储备。下分专题文章知识库、产品架构与规则、案例与反例库、管理与研发交付。
专业文章四域：运动、饮食、心态与恢复、通用基础；运动保留 HYROX、羽毛球、骑行、射击、跑步、田径分类及其完整文章。不预先创建无内容的更多专项。

## 文章与知识单元
完整正文供人阅读；最小单元供检索。单元可跨多个段落，但必须包含理解判断所需的条件，不机械按长度切碎。
知识单元字段由相邻模拟 Skill 的 contracts/knowledge-unit.schema.json 定义：稳定 id/title/category/content/conditions/boundaries/sources/evidence_type/review_status/reviewer/reviewed_at/source_doc_id/source_revision/valid。
ID 建议 NM-领域-短名；后续改文案保留 ID，发生拆分或合并则记录继承关系。引用内容要与原文对应，专家经验不能包装成学术结论。
evidence_type 与 review_status 是两个轴：expert_experience 可被专家确认，但仍不是研究共识。无证据类型、无适用范围或处于争议时不默认上线检索。
文献链接只是证据入口，正文应包含实际内容。没有转载许可不要整篇复制版权文章；整理机制与方法并引用，开放许可全文保留许可与作者信息。

## 审阅与改动
候选保留原文与新文、目标章节、基准 revision、专家会话引用、原因和未知。采纳后记录变更 ID、读回确认版本、目标链接；正文不放聊天口水话或语气策略。
讨论一个点不代表整篇已审阅。来源变化仅让受影响单元回到待复查，不抹掉历史记录。
产品改进意见进入单独文档，并标待产品确认；不自动修改用户问答预算、K或生产系统。
案例明确来源为构造/真实脱敏/论文案例。模拟用户回答、专家评论和 Coach 文案分栏标识；素材来自明星运动员时要有可核验出处，不强制匹配。

## 研发交接
目录入口导航 + 原文章 Markdown + manifest + 单元 JSONL + 未决/排除清单 + 版本记录。
manifest 保留文档 ID、URL、分类、revision、抓取时间和内容 hash；原权限不能靠有链接替代，生产检索需做权限过滤。
默认只将有效、已确认、来源版本匹配的专业单元列为 rag_eligible；其他资源保留可检视，但不默认注入终端用户回答。
现有大部分文章未逐点审阅，初始化索引标 unreviewed；既有明确专家补充应单独复核与记录，不能据此整篇标 confirmed。
