# 场景与结构化输入

读取相关问题包的输入、问题、判断和行动卡；遵守 [会话数据约定](../nuromova-expert-coach/references/session-contract.md)。专家未给主题时使用当前 HYROX 问题包，未指定运动阶段时从包内情境推导并说明。

1. 明确本例要检验的判断分支，例如“昨天加练是否影响今天关键课”。不要先把假设设为事实。
2. 生成 `scenario.md`，含 session_id、scenario_id、scenario_version、synthetic=true、目标、事件阶段、时间线及逐项事实。每条事实具有 id、值、单位（如适用）、发生时间、来源、状态。状态使用 known / unknown / denied / conflicting；缺失不等于否定，矛盾保留各方说法。
3. 区分 Coach 起始可见信息和后续回答。起始事实不透露隐藏原因；尚未回答的信息保持 unknown。模拟用户由专家扮演是默认方式。需要预设角色信息时单独保存 `athlete-role.md`，不混入 Coach 输入。
4. 标注数值为构造值，检查单位、事件顺序和身份一致性，不将构造阈值变为知识结论。不同变式显式改变相关事实，不只改随机种子或案例名称。
5. 输出简短场景和起始结构化输入，交给 Coach 模拟。不得在本步骤预先输出“正确诊断”。

比较分支时从同一基线复制并增加版本，记录改动字段；至少可覆盖支持、否定、记不清及信息冲突。专家调整事实后创建新版本，保留原始记录。

如果同一会话已读到角色隐藏信息，后续只能称为带上下文的演示；要验证信息隔离，需要另行运行只接收可见输入的模型环境，并记录实际运行方式。不得仅凭“忽略上文”声称隔离成功。
